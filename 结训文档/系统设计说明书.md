### 1.2 架构说明

| 层级 | 技术栈 | 职责 |
|------|--------|------|
| 前端层 | Vue 3 + TypeScript + Element Plus + Leaflet | 用户界面展示、交互逻辑、状态管理、地图可视化 |
| 网关层 | Vite/Nginx | 反向代理、路由转发、跨域处理 |
| 后端层 | Spring Boot 3.2 + Spring Security + JWT + Spring Data JPA + 高德地理编码服务 | 业务逻辑处理、身份认证、接口管理、地理编码、JPA实体BigDecimal映射坐标 |
| AI服务层 | FastAPI + LangGraph + RAG + BAAI/bge-small-zh-v1.5 | AI方案生成、多Agent工作流编排、知识库检索、情报分析、方案审查 |
| LLM层 | vLLM + Qwen2.5-7B-Instruct | 大语言模型推理服务 |
| 数据层 | MySQL + PostgreSQL + Redis + MinIO | 业务数据、向量数据、缓存、文件存储 |
| 外部服务 | 高德地图API | 地理编码服务（地址转经纬度） |

#### AI服务架构详解

AI服务基于 **FastAPI** 框架构建，集成了 **LangGraph 多Agent编排**、**RAG检索增强生成**、**向量化知识库** 和 **方案智能审查** 等核心能力。服务接收灾情描述，通过多Agent协作自动完成情报分析、预案检索、资源调度、方案生成和合规审查，最终输出一份结构化的应急处置方案。

**AI服务核心能力**：
- **情报分析Agent**：从灾情描述提取结构化信息（类型、等级、位置、影响人口）
- **RAG检索Agent**：基于向量相似度从知识库检索相关应急预案
- **资源调度Agent**：根据灾害类型从MySQL查询可用资源
- **方案生成Agent**：结合情报、预案、资源生成完整处置方案
- **方案审查Agent**：规则检查 + LLM深度审查，评分并判断是否通过

## 3. 时序图

### 3.1 灾情上报流程

```mermaid
sequenceDiagram
    participant User as 用户(VIEWER)
    participant FE as 前端
    participant BE as 后端(Spring Boot)
    participant Amap as 高德地理编码服务
    participant AmapAPI as 高德地图API
    participant DB as MySQL数据库
    participant MinIO as MinIO文件存储
    
    User->>FE: 填写灾情信息 + 选择图片
    FE->>BE: POST /api/incident/report (multipart/form-data)
    BE->>Amap: geocode(location地址)
    alt 命中本地城市坐标缓存
        Amap-->>BE: 返回经纬度
    else 调用高德API
        Amap->>AmapAPI: GET /v3/geocode/geo
        AmapAPI-->>Amap: 返回地理编码结果
        alt 高德API调用成功
            Amap-->>BE: 返回经纬度
        else 高德API调用失败
            Amap->>Amap: 降级模糊匹配
            Amap-->>BE: 返回经纬度或null
        end
    end
    BE->>MinIO: 上传图片
    MinIO-->>BE: 返回图片URL
    BE->>DB: INSERT INTO incidents (含latitude/longitude)
    DB-->>BE: 返回插入结果
    BE-->>FE: {"code": 0, "data": {"incidentId": "...", "imageUrls": [...]}}
    FE-->>User: 上报成功提示
```

### 3.2 方案生成流程

```mermaid
sequenceDiagram
    participant User as 用户(OPERATOR)
    participant FE as 前端
    participant BE as 后端(Spring Boot)
    participant AI as AI服务(FastAPI)
    participant RAG as RAG检索
    participant Resource as 资源调度
    participant LLM as vLLM
    participant PG as PostgreSQL
    participant MySQL as MySQL数据库
    
    User->>FE: 选择灾情，点击生成方案
    FE->>BE: POST /api/plan/generate {"incidentId": "..."}
    BE->>MySQL: 查询灾情详情
    MySQL-->>BE: 返回灾情信息
    BE->>AI: POST /api/v1/generate-plan {"description": "..."}
    
    AI->>LLM: 情报分析Agent（提取结构化信息）
    LLM-->>AI: 返回分析结果
    
    AI->>RAG: RAG检索（查询pgvector）
    RAG->>PG: SELECT * FROM knowledge_chunks ORDER BY embedding <=> query LIMIT 3
    PG-->>RAG: 返回3条预案片段
    RAG-->>AI: 返回检索结果
    
    AI->>Resource: 资源调度Agent（查询可用资源）
    Resource->>MySQL: SELECT * FROM emergency_resource WHERE available_stock > 0
    MySQL-->>Resource: 返回可用资源列表
    Resource-->>AI: 返回调度结果
    
    AI->>LLM: 方案生成Agent（生成完整方案）
    LLM-->>AI: 返回方案内容
    
    AI->>LLM: 方案审查Agent（审查方案）
    LLM-->>AI: 返回评分和建议（如不通过则重试）
    
    AI-->>BE: {"plan": "...", "citations": [...]}
    BE->>MySQL: INSERT INTO plans
    MySQL-->>BE: 返回planId
    BE-->>FE: {"code": 0, "data": {"planId": "..."}}
    FE-->>User: 方案生成成功，显示方案内容
```

### 3.3 资源调度流程

```mermaid
sequenceDiagram
    participant User as 用户(RESOURCE_MANAGER)
    participant FE as 前端
    participant BE as 后端(Spring Boot)
    participant Redis as Redis分布式锁
    participant MySQL as MySQL数据库
    
    User->>FE: 选择资源，输入调度数量
    FE->>BE: POST /api/resource/lock {"resourceId": "...", "quantity": 100}
    BE->>Redis: 获取分布式锁 resource:{resourceId}
    alt 锁获取成功
        Redis-->>BE: 锁获取成功
        BE->>MySQL: SELECT available_stock FROM emergency_resource WHERE resource_id = ?
        MySQL-->>BE: 返回当前可用库存
        alt 库存充足
            BE->>MySQL: UPDATE emergency_resource SET available_stock -= ?, locked_stock += ?
            BE->>MySQL: INSERT INTO resource_dispatch_record
            MySQL-->>BE: 操作成功
            BE->>Redis: 释放锁
            BE-->>FE: {"code": 0, "data": {"success": true}}
            FE-->>User: 调度成功
        else 库存不足
            BE->>Redis: 释放锁
            BE-->>FE: {"code": -1, "message": "可用库存不足"}
            FE-->>User: 库存不足提示
        end
    else 锁获取失败
        Redis-->>BE: 锁获取失败（正在被其他请求处理）
        BE-->>FE: {"code": -1, "message": "资源正在被调度，请稍后重试"}
        FE-->>User: 调度冲突提示
    end
```

#### Agent工作流状态定义

```python
class AgentState(TypedDict):
    description: str              # 原始灾情描述
    info: Dict[str, Any]          # 情报分析结果
    retrieved_plans: List[Dict]   # RAG检索到的预案片段
    resources: List[Dict]         # 可用资源列表
    plan: str                     # 生成的处置方案
    review: Dict[str, Any]        # 方案审查结果
    messages: Annotated[List, add] # 执行日志消息列表
    retry_count: int              # 方案重试计数
```

#### Agent节点说明

| 节点 | 模块 | 输入 | 输出 | 说明 |
|------|------|------|------|------|
| extract_info | info_extractor.py | 灾情描述 | 结构化情报（类型、等级、位置） | 使用vLLM推理，失败时返回默认值 |
| retrieve_plans | retriever.py | 情报分析结果 | Top-3预案片段 | Embedding + pgvector相似度检索 |
| dispatch_resources | resource_dispatcher.py | 情报分析结果 | Top-15可用资源 | MySQL查询，失败时使用模板 |
| generate_plan | plan_generator.py | 情报+预案+资源 | 完整方案文本 | 7个章节，最多引用3条预案 |
| review_plan | plan_reviewer.py | 方案文本 | 评分+通过状态 | 规则检查 + LLM审查 |

#### 重试机制

- 最多重试3次（MAX_RETRY_COUNT = 3）
- 仅当审查不通过但评分 ≥ 6分时触发重试
- 重试时重新调用方案生成节点

sequenceDiagram

// SecurityConfig.java
@Bean
public CorsFilter corsFilter() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowCredentials(true);
    config.addAllowedOriginPattern("*");
    config.addAllowedHeader("*");
    config.addAllowedMethod("*");

    return new CorsFilter(source);
}
