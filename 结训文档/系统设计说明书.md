## 3. 时序图

### 3.1 灾情上报流程

```mermaid
sequenceDiagram
    participant User as 用户(VIEWER)
    participant FE as 前端
    participant BE as 后端(Spring Boot)
    participant DB as MySQL数据库
    participant MinIO as MinIO文件存储
    
    User->>FE: 填写灾情信息 + 选择图片
    FE->>BE: POST /api/incident/report (multipart/form-data)
    BE->>MinIO: 上传图片
    MinIO-->>BE: 返回图片URL
    BE->>DB: INSERT INTO incidents
    BE->>DB: INSERT INTO incident_reports
    DB-->>BE: 返回插入结果
    BE-->>FE: {"code": 0, "data": {"incidentId": "...", "imageUrls": [...]}}
    FE-->>User: 上报成功提示
```

### 3.2 方案生成流程

```mermaid
sequenceDiagram
    participant User as 用户(OPERATOR)
    participant FE as 前端
    participant BE as 后端(Spring Boot)
    participant AI as AI服务(FastAPI)
    participant RAG as RAG检索
    participant Resource as 资源调度
    participant LLM as vLLM
    participant PG as PostgreSQL
    participant MySQL as MySQL数据库
    
    User->>FE: 选择灾情，点击生成方案
    FE->>BE: POST /api/plan/generate {"incidentId": "..."}
    BE->>MySQL: 查询灾情详情
    MySQL-->>BE: 返回灾情信息
    BE->>AI: POST /api/v1/generate-plan {"description": "..."}
    
    AI->>LLM: 情报分析Agent（提取结构化信息）
    LLM-->>AI: 返回分析结果
    
    AI->>RAG: RAG检索（查询pgvector）
    RAG->>PG: SELECT * FROM knowledge_chunks ORDER BY embedding <=> query LIMIT 3
    PG-->>RAG: 返回3条预案片段
    RAG-->>AI: 返回检索结果
    
    AI->>Resource: 资源调度Agent（查询可用资源）
    Resource->>MySQL: SELECT * FROM emergency_resource WHERE available_stock > 0
    MySQL-->>Resource: 返回可用资源列表
    Resource-->>AI: 返回调度结果
    
    AI->>LLM: 方案生成Agent（生成完整方案）
    LLM-->>AI: 返回方案内容
    
    AI->>LLM: 方案审查Agent（审查方案）
    LLM-->>AI: 返回评分和建议（如不通过则重试）
    
    AI-->>BE: {"plan": "...", "citations": [...]}
    BE->>MySQL: INSERT INTO plans
    MySQL-->>BE: 返回planId
    BE-->>FE: {"code": 0, "data": {"planId": "..."}}
    FE-->>User: 方案生成成功，显示方案内容
```

### 3.3 资源调度流程

```mermaid
sequenceDiagram
    participant User as 用户(RESOURCE_MANAGER)
    participant FE as 前端
    participant BE as 后端(Spring Boot)
    participant Redis as Redis分布式锁
    participant MySQL as MySQL数据库
    
    User->>FE: 选择资源，输入调度数量
    FE->>BE: POST /api/resource/lock {"resourceId": "...", "quantity": 100}
    BE->>Redis: 获取分布式锁 resource:{resourceId}
    alt 锁获取成功
        Redis-->>BE: 锁获取成功
        BE->>MySQL: SELECT available_stock FROM emergency_resource WHERE resource_id = ?
        MySQL-->>BE: 返回当前可用库存
        alt 库存充足
            BE->>MySQL: UPDATE emergency_resource SET available_stock -= ?, locked_stock += ?
            BE->>MySQL: INSERT INTO resource_dispatch_record
            MySQL-->>BE: 操作成功
            BE->>Redis: 释放锁
            BE-->>FE: {"code": 0, "data": {"success": true}}
            FE-->>User: 调度成功
        else 库存不足
            BE->>Redis: 释放锁
            BE-->>FE: {"code": -1, "message": "可用库存不足"}
            FE-->>User: 库存不足提示
        end
    else 锁获取失败
        Redis-->>BE: 锁获取失败（正在被其他请求处理）
        BE-->>FE: {"code": -1, "message": "资源正在被调度，请稍后重试"}
        FE-->>User: 调度冲突提示
    end
```

## 7. 安全设计

### 7.1 认证机制

```mermaid
sequenceDiagram
    participant User as 用户
    participant FE as 前端
    participant BE as 后端
    participant DB as MySQL
    participant JWT as JwtUtil
    
    User->>FE: 输入用户名和密码
    FE->>BE: POST /api/auth/login
    BE->>DB: SELECT * FROM users WHERE username = ?
    DB-->>BE: 返回用户信息
    BE->>BE: BCrypt验证密码
    alt 验证成功
        BE->>JWT: 生成Token（包含username、role）
        JWT-->>BE: 返回Token
        BE-->>FE: {"code": 0, "data": {"token": "...", "userInfo": {...}}}
        FE->>FE: 存储Token到Pinia
        FE-->>User: 登录成功
    else 验证失败
        BE-->>FE: {"code": 401, "message": "用户名或密码错误"}
        FE-->>User: 登录失败提示
    end
```

// SecurityConfig.java
@Bean
public CorsFilter corsFilter() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowCredentials(true);
    config.addAllowedOriginPattern("*");
    config.addAllowedHeader("*");
    config.addAllowedMethod("*");
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return new CorsFilter(source);
}
